OWNER SETUP - SIMPLE GUIDE

WHAT IS THE OWNER?
- One Admin is the "owner". This is stored separately from the Admin role.
- All Admins can manage accounts.
- Only the owner can delete or demote another Admin.
- Only the owner can edit the owner account.
- The owner account can't be deleted or demoted.


EXISTING INSTALLATIONS (do this once after deploying)
1. Open a terminal in the Backend folder.
2. Run:
     npm run migrate:owner
3. The oldest Admin (by creation date) becomes the owner.
4. Safe to run again. A valid owner is never replaced.
5. If you skip this, Admin Settings will say owner-only actions are unavailable.


NEW INSTALLATIONS
- Running "npm run seed:admin" makes the first Admin the owner automatically.


TRANSFERRING OWNERSHIP
1. The owner goes to Admin Settings.
2. Pick another existing Admin.
3. Re-enter your password and confirm.
4. Ownership changes right away. The old owner stays an Admin but loses owner-only powers.


EMERGENCY RECOVERY (if the owner is unavailable or the owner record is broken)
Setup (by a trusted operator):
1. Generate a random secret (32+ characters):
     node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
2. Put it in Backend/.env as:
     OWNER_RECOVERY_CODE=<your secret>
3. Restart the backend.
4. Give the code only to the person authorized to do the recovery.
   Never commit it or share it with regular Admins.

Using it:
1. Any signed-in Admin opens the recovery form in Admin Settings.
2. Select an existing Admin to become owner.
3. Enter your own password and the recovery code, then confirm.
4. The current owner loses owner-only powers (unless they were the one selected).

Rules:
- Each code works only once. (Only a hash of used codes is kept, never the code itself.)
- Before the next recovery, set a NEW random code in .env and restart the backend.
- Never reuse an old code.


IMPORTANT
- Don't use "npm run migrate:owner" to change a valid owner. It will not change it.
